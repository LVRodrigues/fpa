Introduction to Function Point Analysis

Function Point Analysis (FPA) is a software measurement technique that quantifies the functionality provided to the end user based on a requirements specification. It is used to estimate the size, effort, and cost of software development. Here is an overview of the method:

Steps of Function Point Analysis

  1. Identification of System Boundaries:
    • Define the boundaries of the system to be measured. The boundary separates the system from the external environment.
  2. Counting Data Functions:
    • Internal Logical Files (ILF): Sets of data or information that are maintained within the system.
    • External Interface Files (EIF): Sets of data or information that are maintained outside the system but are used by the system.
  3. Counting Transactional Functions:
    • External Inputs (EI): Processes that receive data or information from the user.
    • External Outputs (EO): Processes that send data or information to the user.
    • External Inquiries (EQ): Processes that involve querying data or information by the user.
  4. Assigning Weights to Functions
    • Each type of function (ILF, EIF, EI, EO, EQ) is assigned a weight based on complexity (Low, Medium, High).
  5. Calculating Unadjusted Function Points (UFP)
    • Multiply the quantity of each type of function by its respective weight and sum the results.
    • This step is performed automatically by the system.
  6. Adjusting Function Points
    • Apply adjustment factors based on general characteristics of the system, such as performance, security, etc. This results in the Adjusted Function Points (AFP).
    • The adjustments are recalculated automatically by the system.

Formula

AFP = UFP x [0.65 + (0.01 x Σ(Adjustment Factors))]

Where:

  • AFP (Adjusted Function Points): final value that represents the adjusted measure of the software's functionality, taking into account various complexity factors.
  • UFP (Unadjusted Function Points): initial measure of the software's functionality, calculated based on the number and complexity of data and transactional functions without any adjustments.
  • Σ(Adjustment Factors): the sum of all adjustment factors that account for various characteristics of the system, such as performance, security, and other attributes that affect its complexity.
  • 0.65: constant factor that represents a baseline level of complexity for the software system.
  • 0.01: a conversion factor that converts the adjustment factors from percentage points to a decimal form.

The formula for calculating Adjusted Function Points (AFP) takes into account the Unadjusted Function Points (UFP) and adjusts them based on various factors that affect the system's complexity and performance. The constant factor 0.65 represents a baseline level of complexity, while the sum of the adjustment factors, multiplied by 0.01, accounts for additional complexities. This adjustment ensures that the final AFP value accurately reflects the overall functionality and complexity of the software system.

Benefits of FPA

  • Accurate Estimates: Helps provide more accurate estimates of effort and cost.
  • Project Comparison: Allows comparison of different software projects.
  • Productivity Measurement: Facilitates the measurement of the development team's productivity.
  • Resource Planning: Helps plan resources and schedules for software projects.

Function Point Analysis is a standardized and widely used technique in the software industry to measure the functionality and complexity of software systems.
